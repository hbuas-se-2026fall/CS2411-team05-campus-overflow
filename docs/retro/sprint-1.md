## 1. 匿名卡片汇总（每位成员贴 3 张，本栏匿名归并）

### ✅ Start（开始做 —— 值得尝试的新做法）
1. 前后端按 OpenAPI 契约并行开发，前端先据 `/v3/api-docs` 生成类型与 Mock，避免联调集中返工。
2. 用 Gherkin 验收用例（US-*.feature）驱动开发，验收标准写在前、实现在后。
3. 每次 PR 合并前先确认 CI 转绿，再由 reviewer 合并，减少"先合后修"。

### 🛑 Stop（停止做 —— 阻碍/低效的做法）
1. 不要在跨模块边界上直接相互调用内部类，统一走 `*-api` 端口或领域事件，避免依赖环。
2. 不要积压 PR 到 Sprint 尾才合并，按任务及时 review。
3. 不要再出现忽略单元测试直接提交导致回归的情况，领域测试必须随功能交付。

### 🔄 Continue（继续做 —— 行之有效的做法）
1. 保持 DDD 分层（api / domain / application / infrastructure / interfaces），用 ADR 记录关键决策。
2. 保持看板实时更新，任务卡片按 To Do → In Progress → In Review → Done 流转。
3. 保持站会同步进度与阻塞，SM 及时协调。
