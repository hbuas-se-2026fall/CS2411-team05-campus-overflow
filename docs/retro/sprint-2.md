## 1. 匿名卡片汇总（每位成员贴 3 张，本栏匿名归并）

### ✅ Start（开始做 —— 值得尝试的新做法）
1. 尽早接入 CI（架构约束检查 + 构建 + 测试），让"模块化单体不退化成大泥球"由机器持续验证。
2. 跨上下文依赖一律只走 `*-api` 发布语言，编译期即强制边界。
3. 计数器类字段（分数 / 回答数）用原子 UPDATE 维护，避免"读-改-写"并发覆盖。

### 🛑 Stop（停止做 —— 阻碍/低效的做法）
1. 不要在未查 CI 红灯原因时盲目合并，红灯应"定位根因 → 修复 → 转绿"再合。
2. 不要遗留跨模块 BUG 到下个 Sprint，一旦发现立即修复。
3. 不要在前端本地缺少依赖（node_modules）时声称"build 通过"，验证以真实构建为准。

### 🔄 Continue（继续做 —— 行之有效的做法）
1. 保持领域对象与 JPA 实体分离（ADR-008），领域测试毫秒级、无容器。
2. 保持按限界上下文分包（co-identity / co-qa / co-reputation / co-discovery）。
3. 保持文档与代码同步沉淀（ADR / backlog / 错误码）。
